# Security notes: the server and the interface

What this slice relies on, and what it does not do. Each claim below has a test; the file named after it is where to look. Nothing here is a promise about a network, a second person or a machine you do not trust: this is one person on one machine.

## What the server guarantees

- **It answers only on `127.0.0.1`, and only to its own origin.** The socket is bound to `127.0.0.1` and no other address (`tests/server/boundaries.test.ts`, which also allows `Bun.serve` nowhere but `src/server/app.ts`). A request must carry `Host: 127.0.0.1:<port>` exactly; `localhost:<port>` is refused with a line naming the right address, so there is one origin to reason about. An `Origin` that is not the server's own, a `Sec-Fetch-Site` of `cross-site`, a `POST` with no `Origin` or not `application/json`, any method other than `GET` and `POST`, and a body over 1 MiB are all refused before a handler runs. No `Access-Control-*` header is ever sent. (`tests/server/guard.test.ts`, `tests/server/boundaries.test.ts`.)
- **There is no sign-in.** One person, one machine. Whoever can open a connection to `127.0.0.1` on this machine is that person. The server names the actor itself (`{ kind: "human", id: <configured user> }`), and a request body that names an actor is refused.
- **Roles are checked on the server, and there is one configured role.** Every read and every command is checked against `config.role` before it runs, so hiding a control in the page is never the only check. The role comes from the configuration file, not from the request: nothing in a request can raise it. A requester or leader view may read the page and little else. (`tests/server/guard.test.ts`, `tests/server/commands.test.ts`, `tests/server/boundaries.test.ts`.)
- **A command writes entries and returns.** It never advances the run on its own; only the commands the pipeline contract names do, and for no other. A `GET` never writes an entry.
- **The `http`, `trino` and local-model connections refuse the server's own address.** `serve` hands the server's `host:port` to the connector pool and to the model providers. A source or model endpoint whose location is that port, under any loopback name (`127.0.0.1`, `localhost`, `[::1]`), is refused when it is built and again before each request, because the port may not be known until the server is listening. (`tests/modules/own-server.test.ts`, `tests/cli/serve.test.ts`, which starts `serve` and watches a query to such a source be refused.)

## What the page guarantees

- **The page is a constant.** It is a fixed document that loads one script and one stylesheet; no data is ever written into it. It runs under `default-src 'none'; script-src 'self'; style-src 'self'; connect-src 'self'; img-src 'self' data:; base-uri 'none'; form-action 'none'; frame-ancestors 'none'; require-trusted-types-for 'script'; trusted-types 'none'`. There is no inline script, no inline style and no `unsafe-*` source. (`tests/web/browser-run.test.ts` checks, in a real browser, that the page has none, that `document.body.innerHTML = ...` throws a `TypeError`, that every request the page made went to its own origin, and that the browser reported no script exception, console error or policy violation.)
- **The page builds no HTML from data.** Every element is made from a fixed list of tags and properties; text goes in as text; a link is made only for `https`, or for a blob or bundle of this server.
- **The injection lint is a guard and Trusted Types is the barrier.** `tests/web/lint.test.ts` fails the build if code under `src/web` uses an HTML sink, but a lint reads source and can be walked around by code it cannot see. What stops an HTML sink from working is the browser: `require-trusted-types-for 'script'` with `trusted-types 'none'` makes every such assignment throw, whatever the code looked like. Treat the lint as the early warning and the policy as the enforcement. The policy is only as good as the browser that enforces it.
- **Blobs and bundle files are attachments and never pages.** They are served with `Content-Disposition: attachment`, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: default-src 'none'; sandbox`, and a media type of `application/json`, a plain-text type, or `application/octet-stream`; a blob recorded as `text/html` is served as bytes. A path is never built from a request: a blob is found by its hash among the references an entry records, and a bundle file is read out of the bundle blob the `product.published` entry names, by a name the bundle's manifest lists. (`tests/server/evidence.test.ts`, `tests/server/boundaries.test.ts`.)

## What reaches the browser

- **Entries and blobs go to the browser exactly as recorded.** The browser folds the same entries the server does and must reach the same state, so an entry cannot be rewritten on the way. This is safe because entries and blobs hold no secret value by construction: a credential is named in a manifest, read from the environment when a query is sent, a response that echoes it is refused, and it is never written. A test plants a credential, runs a whole case to publication, and looks for the value and its name in every response, including the entry stream and every blob. (`tests/server/boundaries.test.ts`, `tests/server/evidence.test.ts`.)
- **They may name where a source is.** A recorded query includes the text that was sent and the address it was sent to, and entries name the sources, models and accounts the case used. Anyone who can read a case can read these. If a location is itself sensitive, it should not be in a source's manifest.
- **Everything the server derives is a view with locations and credential names removed.** Source descriptions leave out `location`, `credential`, `user`, folders and roots; manifest problems carry paths relative to their module root; and text from a source error, a manifest problem or an unexpected exception goes through the same scrub before it is sent. Derived views are the reference, the model list, the agent's context, the routes, the custody report and the bundle preview. (`tests/server/reads.test.ts`, `tests/server/boundaries.test.ts`.)
- **A blob that only a skipped entry refers to is still served.** The fold skips an entry whose payload is the wrong shape and records it in `skipped`. The server does not use the fold to decide what to serve: it serves any blob that an entry of the case names at a typed blob position, skipped or not. Such an entry is chained, its position is typed, and the browser already holds the raw entry, so nothing is disclosed that was not already sent. A hash that no entry names, a hash at a position that is not a blob field, and another case's blob are 404. (`tests/server/boundaries.test.ts`.)

## What this does not do

- **Check programs are not confined to a folder.** The form checks of the pipeline run only from trusted roots, from a copy of the bytes that were hashed, with a stripped environment (no credential, only `PATH` and a locale) and a time limit that also ends what they start. They are not sandboxed: a program runs as the person who started the server and can read what that person can read. Do not mark a root as trusted unless you would run its programs. (`tests/pipeline/checks.test.ts`.)
- **`localhost` is still trusted by name for a model on this machine.** A model manifest that says `where: machine` is accepted when its host is `127.0.0.1`, `localhost` or `[::1]`, and nothing checks what is listening there or that `localhost` resolves to this machine. A hosts file or resolver that points `localhost` elsewhere would send prompts there. This belongs with the real run (plan 5), which will decide whether to require a numeric address.
- **It does not defend against another person or process on this machine.** Any local process can connect to the port and, by setting the `Host` and `Origin` headers itself, act as the person. The checks protect against a web page in the person's browser, not against code running next to the server.
- **It does not use TLS and does not authenticate.** Traffic is on the loopback interface in the clear.
- **It does not stop hostile text in data.** Source data and model output are untrusted text. The interface shows them as text and the pipeline treats them as data, but a source title or a quality note can still say something misleading; its prompt-injection surface is carried to plan 5. Agents can only read and propose, so the worst outcome is a wasted query or a bad proposal, and both are in the ledger.
- **It does not limit the stream's memory use.** The entry stream has no backpressure limit; a reader that never reads can make the server hold its pending output.
